# Testing and repeatability

- Python and built-in SQLite are sufficient to reproduce the SQL and file-archive examples.
- Synthetic inputs are deterministic and generated by `tools/demo_db.py`; output CSVs are generated by `tools/generate_synthetic.py`.
- Tests are under `tests/test_sql_projects.py` and `tests/test_automation.py`, executable using `python -m unittest discover -s tests -v`.
- The SQL suite includes reconciliation grain, event-type-specific approval, missing timestamps, before/after scenario separation, carrier concentration, order-grain cost aggregation, one-to-many duplication prevention, latest-record selection, and as-of order selection.
- The archive suite checks extension filtering, safe filenames, repeat writes, overwrite behavior, year boundary and invalid weeks.
- Sample output statistics are intentionally invented. A passing test here **does not** establish the original Power BI model or production flow is correct.
- DAX and Power Query example snippets should be individually validated in a blank Power BI Desktop project using the generated CSVs; there is no automated DAX/M engine included in this package.
